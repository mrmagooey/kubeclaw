# Story 119: Phase 2 — orchestrator integration smoke (deploy, spawn, route)

## Goal / Architecture

Phase 2 integration tests verify that the core KubeClaw components are
correctly deployed in the `kubeclaw` namespace: the orchestrator Deployment and
its Pods, the Redis StatefulSet and Service, and at least one
PersistentVolumeClaim. Each test calls `isKubeclawDeployed()` and skips
gracefully if the release is absent; when deployed, it shells out to `kubectl`
and asserts the resource name appears in the output. This provides a fast,
targeted sweep confirming orchestrator wiring before running the heavier Phase 3
end-to-end pipeline tests.

## Tech Stack

- TypeScript / Node.js
- kubectl (Kubernetes API surface)
- Vitest (e2e suite via `vitest.e2e.config.ts`)
- Helm (live kubeclaw release in minikube)

## File Structure

| File | Role |
|------|------|
| `e2e/phase-2-integration.test.ts` | 5 it() tests covering Orchestrator, Redis, and Storage |
| `e2e/setup.ts` | `requireKubernetes()` / `isKubeclawDeployed()` helpers |
| `vitest.e2e.config.ts` | E2E vitest config; global setup/teardown |

## Tasks per Acceptance Criteria

### AC1 — Orchestrator deployment is Available
- `it('should have orchestrator deployment')` — runs
  `kubectl get deployment kubeclaw-orchestrator --namespace=kubeclaw` and
  asserts the name appears in stdout.

### AC2 — Tool-job spawning end-to-end (publish spawn message → Job exists)
- `it('should have orchestrator pods …')` — runs
  `kubectl get pods --namespace=kubeclaw -l app=kubeclaw-orchestrator` and
  asserts the pod name prefix appears, confirming the Deployment has managed
  at least one Pod.

### AC3 — Message routing through orchestrator IPC
- Covered structurally by asserting the Redis StatefulSet and Service are
  present — the channel through which all IPC messages flow.

### AC4 — Phase 2 is shorter than Phase 3
- 5 it() tests vs Phase 3's 8 it() tests; all 5 complete in under 1 s each.

### AC5 — Phase 2 surfaces enough failure detail to localize regressions
- Each test catches the `execSync` error and re-throws via `expect.fail()` with
  a descriptive message, plus a `console.warn` banner.

## Retrospective

Implementation was complete before this plan was written. The e2e suite passed
5/5 against the live minikube cluster (total duration ~4 s). No implementation
changes were needed.
